# 产品方案：文本处理中台

> 状态：设计稿（未实现） · 日期：2026-08-22 · 模式：纯前端离线

## 一、定位

用户只输入一段文本，不切换页面，一次性产出所有与这段文本相关的处理结果。核心哲学是"一次输入、全部产出"，而非"先在几十种算法里挑一个再输入"。

本工具是整套工具箱的"文本入口"，其**多输出 Tab 框架**搭好后，后续新增任意算法只需从框架侧再挂一个子项即可，边际成本极低。

## 二、目标用户

- 开发者：需要快速编解码、算哈希、看统计、识别时间戳。
- 普通用户/测试：粘贴 JSON/URL/Base64 想一键看清里面是什么。
- 运维/分析：对文本反复做多轮解码探测。

## 三、页面布局

遵循 `docs/superpowers/specs/2026-08-18-tool-dev-convention.md` 的观感约定。

```
┌─────────────────────────────────────────────────────────────┐
│ ← 返回 | 文本处理中台                     [复制输入][清空]     │
├──────────────────────────────┬──────────────────────────────┤
│  输入区（多行 textarea）       │  [编解码] [哈希] [统计]      │
│   · 自动类型探测徽标          │  [时间戳] [智能解码] (垂直 Tab)│
│   · Ctrl+Enter 可刷新         │  ─────────────────────────   │
│                              │  结果子面板                    │
│                              │  · 每子项有 [复制][下载]        │
└──────────────────────────────┴──────────────────────────────┘
   底栏：字符数 · 行数 · 字节数（UTF-8) · 已识别类型
```

- 左窄右宽的 `grid md:grid-cols-[1fr,1.6fr]`，移动端上下堆叠。
- 右侧顶部是**算法大类**的垂直 Tab 组，点击某一类后，其下再展开**该类的具体子项**。

## 四、交互流程

1. 用户在左侧粘贴/输入文本。
2. 左侧自动检测文本类型（JSON / URL / Base64 / UUID / 时间戳 / 十六进制 / 通用文本），在输入框顶部给出轻量徽标提示（不阻断输入）。
3. 右侧默认落在"编解码"类，各算法子项即时渲染结果。
4. 用户点任一 Tab，结果即时刷新；每项结果旁有 `复制` 与 `下载` 按钮。
5. 输入被清空或全空格时，结果区显示空态占位。

## 五、功能详述

### 5.1 编码/解码类

子项（每种算法内部再分"编码结果"与"解码结果"左右同屏）：

| 子算法 | 逻辑 | 需要的额外参数 |
|---|---|---|
| Base64 | 文本 ⇄ Base64 | 无 |
| Base64URL | Base64 的 URL 安全变体 | 无 |
| URL 编码 | encodeURIComponent ⇄ decodeURIComponent | 无 |
| Unicode 转义 | `\u4e2d` ⇄ 中 | 无 |
| 十六进制 | Hex ⇄ 文本 | 无 |
| HTML 实体 | `&amp;` ⇄ `&` | 无 |
| ROT13 | 字母位移 13 | 位移量（默认 13，可改） |
| AES（高阶） | AES-GCM 加解密 | 密钥、模式、盐/IV、填充 |

- 每个子算法 Tab 之下，若需参数（如 ROT13 位移、AES 密钥/轮次/填充），在面板顶部呈现参数表单，参数变化立即重算。
- 某一方向（如解码）对当前文本无意义/失败时，灰显并提示"该方向不适用"。

### 5.2 哈希/校验类

- 子项：MD5、SHA-1、SHA-256、SHA-512、CRC32。
- 输入文本即时计算十六进制摘要；每个哈希一行，右侧复制按钮。
- 对超大文本采用增量方式（流式），避免长文本卡顿（有限度，文本工具通常 < 数 MB）。

### 5.3 统计类

- 字符数（UTF-16 code units）。
- 字节数：UTF-8 编码字节、UTF-16 编码字节（`TextEncoder` 计算）。
- 行数、非空行数。
- 字数（按空白分隔的词）+ 单词数（英文维度）。
- 实时更新。

### 5.4 时间戳识别

- 扫描文本中的数字与日期串。
- 数字若是合理的 Unix 秒（10 位）或毫秒（13 位），给出对应的本地时间与 ISO 时间。
- 若是日期串（如 `2026-08-22 10:30`、`2026/08/22`、`10:30AM`），给出其 Unix 秒/毫秒。
- 每处匹配列出，带复制。

### 5.5 智能解码

- 参考思路：对输入反复尝试常见算法（Base64、URL、Hex、Unicode、ROT、十六进制、JSON 反转义等），每轮后检测结果是否为"更可读"的形态（含可打印字符比例、是否是有效 JSON/URL/Key=Value 等启发式），累积成解码链。
- 输出：候选列表，每条含"当前文本 / 已用一步算法 / 相对上一步的置信度分数 / 建议是否继续"。
- 控制：最大迭代轮次（默认 8，可调）与结果条数上限，避免指数爆炸。
- 该功能按"启发式侦探"定位，不保证 100% 还原，UI 需明示"智能解码为启发式结果，结果仅供参考"。

## 六、数据与状态

- 输入文本**不持久化**（隐私 + 无必要），仅内存状态；刷新即失。
- 主题、字号等少量偏好走 localStorage（key: `texthub:prefs`）。
- 支持从本地文件导入文本（`<input type="file">` + `FileReader`），导出为 `.txt`（`Blob` + `download`）。

## 七、技术要点与模块划分

```
src/lib/text/
  detect.ts      # 输入类型探测（JSON/Base64/URL/UUID/时间戳/...）
  encoders.ts    # 各单步编解码纯函数（base64/url/unicode/hex/html/rot）
  aes.ts         # WebCrypto AES-GCM 封装
  hashes.ts      # 基于 WebCrypto 的 SHA 系列 + 增量实现；MD5/CRC32 用小型实现
  stats.ts       # 字符/字节/行/词统计
  timestamp.ts   # 时间戳与日期串双向识别
  smartdecode.ts # 智能解码链 + 置信度打分
src/views/TextHub.vue   # 页面：左输入 + 右 Tab 结果
src/components/text/    # 各子面板组件（每算法一个）
```

- 所有算法层为**纯函数**，输入 string → 输出结构化结果，便于 `vue-tsc` 类型保证与单测。
- AES 用浏览器原生 `crypto.subtle`（WebCrypto），不引入重依赖。

## 八、边界情况

- 空输入 / 全空格：空态占位，不崩。
- 非法编码输入（如非法 Base64、Hex 含非十六进制字符）：标红提示"无法解码"而非报错。
- 超大文本（> 数 MB）：哈希走增量，编解码面板分页或限制展示长度并提示。
- 二进制/emoji 文本：字符数与字节数按 UTF-8 code point 正确区分统计，不歪曲。

## 九、不做的事

- 不做运行期联网；所有算法本地执行。
- 不做文本云端分享 / 历史记录。
- 不做文件内的钉对（svn 式 diff 另议）。
- 不做拼写检查 / 翻译 / 全文检索等语义级能力。
