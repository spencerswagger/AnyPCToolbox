# 产品方案：结构化数据互转

> 状态：设计稿（未实现） · 日期：2026-08-22 · 模式：纯前端离线

## 一、定位

让 CSV / JSON / YAML / TOML / XML / Excel 等具有结构化规则的格式之间自由互转。核心架构是 **`Records` 中间模型**：任何格式进 → `Records` → 任何格式出。新增格式只需写一对"导入/导出 adapter"，远小于两两互转的 M×N 矩阵成本。

## 二、目标用户

- 需要把 Excel 转 CSV、把 JSON 转 YAML、把 CSV 转 JSON 的运营与办公用户。
- 对接数据管道、需要快速转格式的开发者。

## 三、页面布局

```
┌─────────────────────────────────────────────────────────────┐
│ ← 返回 | 结构化数据互转      [导入文件] [导出结果]              │
├─────────────────────────────────────────────────────────────┤
│ 输入格式: [JSON ▾]   源数据编辑区（左半）                       │
├─────────────────────────────────────────────────────────────┤
│  预览表格（可选中列/校验，中间带）                              │
│   │ col1 │ col2 │ col3 │                                      │
│   │ ...                                                       │
├─────────────────────────────────────────────────────────────┤
│ 输出格式: [YAML ▾]   结果编辑区（右半，含复制/下载）              │
└─────────────────────────────────────────────────────────────┘
```

- 三栏语义：**源格式 + 源文本 → 预览表格（校验/纠偏）→ 目标格式 + 结果**。
- 源/目标格式下拉，双向可换（互转），支持 `反向`一键对调。
- 顶层错误横幅（`border-destructive/50`）：解析失败原因定位到行列。

## 四、交互流程

1. 选源格式，粘贴或导入文件 → 解析为 `Records`，中间预览表格渲染。
2. 解析失败：红色横幅提示行列号；成功则显示行数/列数。
3. 可选：预览表格支持调整列顺序、跳过列（处理 Excel/CSV 脏表头）。
4. 选目标格式 → 由 `Records` 即时导出。
5. 结果可复制、导出为对应扩展名文件（`Blob` + `download`）。

## 五、格式支持（分批）

**首批（核心管道）**

| 格式 | 导入 adapter | 导出 adapter | 备注 |
|---|---|---|---|
| JSON | JSON 数组/对象 → Records | Records → JSON | 处理嵌套展开策略 |
| YAML | 解析 → Records | Records → YAML | |
| CSV | 引号/转义/换行/表头 | Records → CSV | |

**次批**

| 格式 | 备注 |
|---|---|
| TOML | 键值/表格 → Records |
| XML | 节点 → Records |
| Excel `.xlsx` | 用 SheetJS 读表 → Records；支持多 sheet 择一 |

**后置 / 独立子工具**
- **XMIND**：`.xmind` 实为 zip 包（含 `content.json`/`content.xml`），有独立的思维导图结构（中心主题 + 节点树 + 边界线），非简单表格，拟作为**独立的高级子工具**（心智图 ⇄ 大纲文本/JSON/Excel），不混入主互转管道。

## 六、数据结构

```ts
interface Cell { value: string | number | boolean | null }
interface Record { columns: string[] }
interface Records { columns: string[]; rows: Cell[][] }
```

- 嵌套（JSON 对象/数组、XML 节点）要定义"展开/扁平化"策略：默认列名为 `a.b.c` 点路径，提供"忽略深层"+ 一列 JSON 字符串两种可选策略。

## 七、数据与状态

- 源文本与结果文本作为页面内状态（URL 不承载大文本，避免超长 hash）；可使用 localStorage 暂存最后一次（key: `datafmt:last`），可选。
- 不引入 IndexedDB（单次转互无大体量持久化需求）。
- 支持本地文件导入/导出。

## 八、技术要点与模块划分

```
src/lib/dataformats/
  records.ts        # Records 类型 + 校验 + 嵌套展开/扁平化工具
  importers/        # 每种格式一个 imp: (text)=>Records
    json.ts
    yaml.ts
    csv.ts
    toml.ts
    xml.ts
    xlsx.ts
  exporters/        # 每种格式一个 exp: (records)=>string
    json.ts
    yaml.ts
    csv.ts
    toml.ts
    xml.ts
    xlsx.ts
src/views/DataFormats.vue
```

- YAML/TOML 解析可引入成熟轻量库（如 `yaml`、`smol-toml`）或自实现最小可用子集；XML 用 DOMParser。
- xlsx 用 SheetJS（`xlsx`）。
- **统一接口契约** `importer/exporter` 是扩展点：加格式 = 加一对文件 + 在下拉注册。

## 九、边界情况

- 空输入 / 空文件：空表格占位。
- 列数不一致（脏 CSV）→ 按最大列补齐空值 + 提示。
- 超大文件（数 MB）：分块解析 + 性能提示，预览表格分页/虚拟滚动。
- 特殊字符（引号、逗号、换行在字段内）的 CSV 正确转义。
- 嵌套过深 JSON：展开策略限制深度，超出转为一列 JSON 串。

## 十、不做的事

- 不做在线数据源 / 联网。
- 不做 XMIND 混入主管道（独立子工具）。
- 不做公式引擎 / 数据清洗透视（仅结构互转 + 基础校验）。
- 不做自定义单元格合并等排版能力（那是表格办公软件职责）。
