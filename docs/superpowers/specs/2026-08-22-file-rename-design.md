# 文件批量重命名设计

> 状态：设计稿（已确认） · 日期：2026-08-22 · 模式：纯前端（File System Access API）

## 定位

用**可视化规则块 + 实时预览**替代传统工具的"模板语法"，降低高上手门槛。用户无需记忆 `%n%`、`{seq}` 占位符，所见即所得。改名**真正写盘**，全程纯前端，无后端命令。

参考对标：https://z.tools/zh/t/file-rename（其模板语法难上手，本设计用图形化规则 + 逐行对照预览化解痛点；写盘机制沿用 FS Access API 思路）。

## 关键机制（用户确认）

1. **纯前端写盘**：用 File System Access API 的 `showDirectoryPicker()` 让用户选一个文件夹（浏览器原生对话框），再对该目录句柄 `getFileHandle()` / 创建新名句柄 / 删除旧名句柄，实现真正的盘上改名。
2. **拖拽选夹**：`dataTransfer.items` 调 `getAsFileSystemHandle()` 拿目录句柄，原生拖拽进文件区。
3. **真实撤销**：IndexedDB（key: `rename:history`）存 `旧名→新名→目录句柄` 映射；撤销时恢复旧柄、删除新柄。IndexedDB 可存目录句柄（结构化克隆支持）。
4. **能力降级**：环境不支持 FS Access API（macOS/Linux 桌面 webview、旧浏览器、HTTP 非 secure 环境）时，`detectFsAccess()` 返回 false，进入**只读模式**：选择/拖拽文件（`<input type=file multiple>` 或传播路径）、预览、导出改名列表，不提供真写盘，顶部横幅明示能力边界。

## 模块划分

```
src/lib/rename/
  build.ts        # buildName(name, rules) 纯函数：单个文件根名 -> 新根名
  preview.ts      # batchPreview(entries, rules) -> [{old,new,changed,skipped,conflict}]
  conflict.ts     # 冲突检测 + 自动补序号（同名冲突消解）
  diff.ts         # 差异高亮：对两个字符串输出 [{text,type:'same'|'add'|'del'}]
  fsaccess.ts     # detectFsAccess() / pickDirectory() / 拖拽 getAsFileSystemHandle / 落盘与撤销
  rules.ts        # 7 种规则的 TS 类型 + 默认值 + 空/边界校验
  history.ts      # IndexedDB：新增 / 撤销 / 清理 撤销栈
src/components/rename/
  RuleBlock.vue     # 通用规则容器（类型下拉 + 参数表单 + 删除/上移/下移）
src/views/Rename.vue
```

- 核心为可测纯函数 `buildName`：改名逻辑与 UI 完全解耦，预览、执行、单测共用同一函数。
- `fsaccess.ts` 的落盘与撤销为浏览器 API 薄封装，可被 mock 测试。

## 数据流

1. 用户选夹/拖入夹 → `pickDirectory()` 返回目录句柄 + 遍历 `dir.entries()` 收集文件项 `{ name, handle, size, mtime }`（`getFile()` 取元信息）。
2. 点击"添加规则"→ 选七种类型之一 → 展开参数表单。
3. 每改参数 → `batchPreview` **即时重算** → 预览区逐行对照，差异高亮（`diff.ts`）。
4. 未命中的行保持原名并灰显；行可取消勾选（跳过）；冲突行红标，"自动加序号"开启后由 `conflict.ts` 消解（改 `new` 并补 deadband）。
5. 点 `应用更改` → 按传入 write 模式：
   - 真写盘：遍历 selected 项，对目录句柄做"建新名 → 删旧名"（先建后删，失败回滚该文件），成功后该批 `旧→新→柄` 写入 IndexedDB。
   - 只读模式：仅导出"原名 → 新名"的改名列表（下载 txt/csv/md）。

## 七种规则（图形化参数，非模板）

| 规则 | 参数 | 示例 |
|---|---|---|
| 查找-替换 | 查找串、替换串、仅首个 | `IMG_` → `Photo_` |
| 前缀 / 后缀 | 添加文本 | `2025-` / `_final` |
| 序号 | 起始、步长、位数、位置(前/后)、分隔符 | 前加 `01_ 02_` |
| 时间戳 | 格式模板(下拉而非自由输入)、来源(当前/文件修改时间) | `20260822_` |
| 大小写 | 全大写/全小写/首字母大写 | `IMG_001`→`img_001` |
| 删除字符 | 从第几位删 N 位 / 删除指定字符集 | 去前 4 位 |
| 扩展名 | 统一替换扩展名 / 保留 | `.jpg` |

- **正则**作为"高级"折叠选项保留在"查找-替换"与"删除字符"内，默认收起。
- `buildName` 只处理**文件根名**（去扩展名），扩展名由"扩展名"规则决定；预览显示完整"原名 → 新名"。

## 冲突与边界处理

- **冲突检测**：批量计算新名后，同名视为冲突，逐文件红标；可整体开启"自动加序号"，由 `conflict.ts` 按预览顺序追加 `(2)`/`(3)`…并回填至 `new` 与预览。
- **拒绝名单**：空名/全空白名、目标名超长、含非法字符 `\/:*?"<>|` → 行红标 + 禁用"应用更改"。
- **Unicode**：全程用文件名原字符串做索引与 diff，中文/空格/emoji 正确保留与高亮。
- **规则未命中任何文件**：提示"该规则对当前文件无影响"。
- **写盘失败**：逐文件 try/catch，新建→删旧两步原子化；失败则把该文件改名回滚，错误汇总到底栏提示。

## 样式

只语义 token：`bg-card`/`bg-border`/`bg-accent`/`bg-destructive` 等；差异高亮用（增）`text-emerald-600 dark:text-emerald-400` /（删）`text-destructive`；交互元素带 `focus-visible:ring-2`。与 `Json.vue`/`IdCard.vue` 观感一致。

## 测试

- `build.ts`、`conflict.ts`、`diff.ts` 为纯函数，构建期 `vue-tsc --noEmit` 保证类型；`fsaccess.ts`/`history.ts` 的浏览器 API 用可注入 mock。
- 关键样例在代码注释列出：替换命中/未命中、序号填充、冲突补序、正则高级项、特殊字符名。
- 项目构建命令 `npm run build`（含 type check）通过为准。

## 不做的事

- 不做后端改名命令（纯前端，FS Access API）
- 不做在线云文件、不做跨文件内容替换、不做正则作默认门槛
- 不兼容 webview 时不做静默改盘（仅只读导出，明示能力边界）
- 不做权限/ACL 等系统级能力
